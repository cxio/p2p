# 名识存储的周期性重洗

> **目的：**
> 消解名识存储位置的可预测性，降级「定向围攻」的确定性。


## 问题

应用的名识通常是固定的，即便是多个，也有限度。

在 DHT 结构化查询中，名识的存储位置由静态异或距离决定。攻击者可以：

1. 对目标名识预先计算其存储区域。
2. 批量生成落入该区域的 Sybil 节点（NodeID）。
3. 垄断该名识的存储与应答位置，扣留记录（拒绝服务），阻滞目标服务成网。

定位精确，且一次布局长期有效，攻击成本低。

自由搜寻可规避定位，但效率较低。本机制在保留结构化查询效率的前提下，试图消解攻击者**确定性布局**的能力。


## 核心机制

以固定时长的时间片周期（**Epoch**）为单位，每个 Epoch 重洗名识的存储位置，存储位置的随机性由 drand 网络/中继提供（`Seed_e`）。


### 随机信标

`Seed_e` 必须满足：Epoch 开始前**不可预测**、开始后**全网一致**、**不可被单方操控**。

- **主用**：drand 公共随机信标（阈值 BLS 签名，每 `30s` 一轮）。Epoch 编号与 drand 轮次均由时间线性派生，节点独立计算，取 Epoch 起始时刻对应的轮次输出作为 `Seed_e`。
- **降级**：drand 是外部信任源，如果信标不可获取（drand 本身问题），节点改由自由搜寻模式注册登记即可。

> **中继服务：**
> 在严格审查环境下，局部地区对 drand 的可访问性可能是一个问题，因此基网需要实现其中继服务。
> 随机信标可验证，基网节点默认提供任意轮次随机数的查询中转。如果某节点无法提供中继查询，切换其它节点即可。


## 位置重洗

存储键由 Epoch 随机种子派生：

```go
// 混合常数：
// 增加 Bit 位复杂性（FxHash 局部）
Mix := 0x517cc1b72722

// 离散度：
// 不同应用根据自己的网络规模，设置不同的值（>0）。
dispelMax := 20

// 离散因子：
// 参与名识键计算，扩充名识的键规模
RandX := (rand.Intn(dispelMax) + 1) * Mix

// 名识键：
// 用于与节点ID比较异或距离。
// Seed_e 由 drand 网络提供的随机数。
// domainTag 域标识 base-net.Reshuffling@v1
StoreKey := Hash256( domainTag || Seed_e || 名识 || RandX )
```

- 名识记录不再存储在"离名识近"的节点，而是存储在离 `StoreKey` 近的节点（Kademlia 路由方式不变）。
- 每个 Epoch 更换 `Seed_e`，全网名识的存储位置整体重洗（新位置变化，不影响旧存储）。
- 发布方与查询者计算的 `StoreKey` 键小范围随机分布，依赖随机碰撞触及目标（**优化**：范围足够小 + 目标足够多）。

> **说明：**
> 这里的「名识记录」指包含名识的节点记录，特指依名识登记。


### 更新周期

- Epoch **6** 分钟更新一次，保留 **10** 个 Epoch 有效。
- 旧 Epoch 中的存储不变，过期（**1**小时）即弃。
- 整轮 10 个 Epoch 结束之前，节点自己主动更新自己的登记。通常提前 1 个 Epoch 进行。
- 查询者可对 10 个 Epoch 内的信息进行检索（随机 Epoch）。


### 写资格与应答资格

只有最新 Epoch 接收登记。新身份要在该 Epoch 起点之前 **8** 分钟就已经连入（构成见 [设计](0.设计.md)），使得攻击者的定向研磨赶不上当前 Epoch 的写资格。

新身份延迟只约束**写资格**，无法同时约束**应答资格**——与 StoreKey 更近的新 NodeID 一旦进入分享，即可挤入「近邻」位置，并影响之前旧的 Epoch。

因此查询应答需要跟踪延迟状态，即只有在该 Epoch 当时已拥有存储者资格的节点，才能作为 k 近邻节点被分享。之后新出现的更近身份可以进入路由表，但不继承该 Epoch 的应答权。这样就可以排除攻击者对查询应答的污染。

写资格满足之后，登记仍受 IP 前缀限额约束，见 [设计](0.设计.md) 的前缀多样性。

> **实现：**
> 写资格用本节点观察到的首次连入时间：早于目标 Epoch 的起点减去 **8** 分钟。
> 最新一个 Epoch 需提前 **8** 分钟连入；再早一个 Epoch 需再提前一个 Epoch 长度，即 `8+6 = 14` 分钟，以此类推……每个更早的 Epoch 都加一个 **6** 分钟。
> 节点应当对当时已有存储者资格的节点按 Epoch 分组，并标注连入时间信息，以在 k 近邻分享时提供。
> 检索者对应答需抱持适度怀疑态度，用自身可控的多路径独立迭代路由，交叉验证，并可结合恰当的 IP 前缀限额。


### 关于离散因子

应用的名识相对固定，而一个节点存储该名识（Key）对应的应用记录（Value）通常有数量上限（比如*100*）。这样，一个应用的入口节点数量就受限了。

> **说明：**
> Kademlia 网络中接受同一 Key 的存储节点有多个（`K=20`），但这只是节点在线的冗余保护，并不能扩展 Key 的 Value 本身的规模。
> 本网络采用 Kademlia 技术，但同一 StoreKey 对应的值（节点信息）本身需要是一个集合（`Key => [Value]`），即多个节点拥有共同的 StoreKey。
>
> 现实中，K 个节点存储的同一 StoreKey 的值集可能并不完全一致（因登记竞争），但节点数量的限制逻辑没有变（整体依然受限）。

加入一个小范围可变的离散因子，可以让名识键（StoreKey）本身多样化，扩大存储者规模。如 dispelMax 取 20，最多可容纳 `20*100 = 2000` 条记录。加上 10 轮 Epoch 最多可达 2 万条。

应用需要根据自身的发展状况，配置恰当的离散度（dispelMax）：小网络有效节点少，离散度就应该小（如取**2**），大网络则可放宽，以充分吸纳节点登记。不过这是应用自己的事。


## 与自由搜寻的分工

- **常态**：结构化查询 + 周期重洗 + 新身份延迟 => 高效且不可被定位攻击。
- **信标失效 / 极端审查**：降级为自由搜寻（随机扩散 + 微广播），以效率换存活。

两者并不是绝对的主备关系，用户可灵活选择：可能需要自由搜寻的隐私性，也可以更看重 DHT 结构化方案的效率。
