# 名识存储的周期性重洗

> **目的：**
> 消解名识存储位置的可预测性，降级「定向围攻」的确定性。


## 问题

应用的名识通常是固定的，即便是多个，也有限度。

在 DHT 结构化查询中，名识的存储位置由静态异或距离决定。攻击者可以：

1. 对目标名识预先计算其存储区域。
2. 批量生成落入该区域的 Sybil 节点（NodeID）。
3. 垄断该名识的存储与应答位置，扣留记录（拒绝服务），阻滞目标服务成网。

定位精确，且一次布局长期有效，攻击成本低。

自由搜寻可规避定位，但效率低。本机制在保留结构化查询效率的前提下，试图消解攻击者**确定性布局**的能力。


## 核心机制

以固定时长的时间片周期（**Epoch**）为单位，每个 Epoch 重洗名识的存储位置，存储位置的随机性由 drand 网络提供（`Seed_e`）。


### 随机信标

`Seed_e` 必须满足：Epoch 开始前**不可预测**、开始后**全网一致**、**不可被单方操控**。

- **主用**：drand 公共随机信标（阈值 BLS 签名，每 `30s` 一轮）。Epoch 编号与 drand 轮次均由时间线性派生，节点独立计算，取 Epoch 起始时刻对应的轮次输出作为 `Seed_e`。
- **降级**：信标不可达时，冻结当前 Epoch 的存储映射（不轮换），直至信标恢复。此期间名识查询自动降级至*自由搜寻*兜底。

> **权衡：**
> drand 是外部信任源，与完全无中心的愿景存在张力。但它只在 Epoch 边界被轻量引用（极小查询），不介入运行时。

理论上，未来 drand 网络的稳定性实际上可以籍由基网本身得到加强，这是一种互补增益的关系。


## 位置重洗

存储键由 Epoch 随机种子派生：

```go
// 混合常数：
// 增加 Bit 位复杂性（FxHash 算法常量）
Mix := 0x517cc1b727220a95

// 离散度：
// 不同应用根据自己的网络规模，设置不同的值。
// 约束：整数，≥ 1
dispelMax := 50

// 离散因子：
// 参与名识键计算，扩充名识的键规模
RandX := rand.Intn(dispelMax) * Mix

// 名识键：
// 用于与节点ID比较异或距离。
// Seed_e 由 drand 网络提供的随机数。
StoreKey := Hash256( Seed_e || 名识 || RandX )
```

- 名识记录不再存储在"离名识近"的节点，而是存储在离 `StoreKey` 近的节点（Kademlia 路由方式不变）。
- 每个 Epoch 更换 `Seed_e`，全网名识的存储位置整体重洗（新位置变化，不影响旧存储）。
- 发布方与查询者计算的 `StoreKey` 键小范围随机分布，依赖随机碰撞触及目标（**优化**：范围足够小 + 目标足够多）。

> **说明：**
> 这里的「名识记录」指包含名识的节点记录，特指依名识登记。


### 更新周期

- Epoch **6** 分钟更新一次，保留 **20** 个 Epoch 有效。
- 旧 Epoch 中的存储不变，过期（**2**小时）即弃。
- 整轮 20 个 Epoch 结束之前，节点自己主动更新（重新登记）自己。**注**：通常提前 1~2 个 Epoch。
- 查询者可对 20 个 Epoch 内的信息进行检索（随机 Epoch）。

> **安全性：**
> 只有在最新的 Epoch 中才会接收登记，攻击者只有**6**分钟的时间窗口。
> 如果结合 Design 中的节点扩散规则（新身份延迟），攻击者的时间窗口会更小（`6-5 = 1` 分钟）。


### 关于离散因子

应用的名识相对固定，而一个节点存储该名识（Key）对应的节点信息（Value）通常有数量上限（比如*100*）。这样，一个应用的入口节点数量就受限了。

> **说明：**
> Kademlia 网络中接受同一 Key 的存储节点有多个（`K=20`），但这只是节点在线的冗余保护，并不能扩展 Key 的 Value 本身的规模。
> 本网络采用 Kademlia 技术，但同一 StoreKey 对应的值（节点信息）本身需要是一个集合（`Key => [Value]`），即多个节点拥有共同的 StoreKey。
>
> 现实中，K 个节点存储的同一 StoreKey 的值集可能并不完全一致（登记竞争），但节点数量的限制逻辑没有变（整体依然受限）。

加入一个小范围可变的离散因子，可以让名识键（StoreKey）本身多样化，从而增加存储者规模。如 dispelMax 取 50，则最多可容纳 `50*100 = 5000` 条节点信息。

应用需要根据自身的发展状况，配置恰当的离散度（dispelMax）：小网络有效节点少，离散度就应该小（如取**10**），大网络则可放宽，以充分吸纳节点登记。

> **安全性：**
> 对于查询，存储者并不会返回目标名识对应的全部节点信息，只会随机提取一部分（且可能含无效信息）。


## 与自由搜寻的分工

- **常态**：结构化查询 + 周期重洗，高效且不可定位。
- **信标失效 / 极端审查**：降级为自由搜寻（随机扩散 + 微广播），以效率换存活。

两者不是主备关系，而是连续谱：重洗的不可预测性越弱，自由搜寻的权重越高。
