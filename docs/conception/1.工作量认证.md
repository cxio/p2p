# 工作量认证（连入）

节点创建连接前需要先执行一个工作量运算，提升连接成本，优化 P2P 连网机制。

工作量算法基于非对称代价的 `Equi-X` PoW 哈希（抗 GPU/ASIC 矿机），连接方需要付出更多的计算，而接受/验证方的计算成本极低。


## 算法

**通用部分：**

```go
import "github.com/cxio/equix-cgo/puzz"

// 命中率：10%
// 固定配置，针对当前流行PC，~150ms 级成本。
threshold := puzz.FromProbability(0.1)
```

**客户端工作量求解：**

```go
// 初始上线时，此集合为空
// 否则为从其它节点接收到的基网身份集。
Nodes := [...]

if len(Nodes) == 0 {
    // 冷启动：绑定目标地址（IP:Port）。
    // 该地址在 IP 报文里。
    binding = ServAddr
} else {
    // 绑定目标身份（NodeID）。
    // 这是应用层材料。
    // IP 报文里有 SPKI 但无 Nonce，因此无法算出 NodeID。
    binding = Nodes[n].NodeID
}

// domainTag 基网的域标签：base-net.Connect@v1
// AppSeed  32 字节，基网库的常量，全网同一套值。
//          升级时可更换，验证时兼容最近 3 个旧值。
// CH.SNI   ClientHello 上的 SNI，增加熵值
// binding  冷启动为 ServAddr，否则为对端 NodeID
// baseInfo 基础信息：domainTag || AppSeed || CH.SNI || binding
baseInfo := domainTag || AppSeed || CH.SNI || binding

// 求解生成：
// Mac mini Pro M4 单核耗时约 ~150ms
// Timestamp 当前时间戳，Unix时间，单位：分钟
// Rand16    16字节随机数，将成为 CH.random 的后半段
// solution  Try 返回的工作量解，2*8 = 16字节。
// seed      验证时本来就要计算的哈希。其前 16 字节用作掩码。
var Rand16, seed, solution
for {
    // 生成新的 Rand16
    Rand16 = ...
    Timestamp := Now / time.Minute

    seed = Hash256(baseInfo || Timestamp || Rand16)
    solution, _ = threshold.Try(seed)
    if solution != nil {
        break // 找到解
    }
}

// 前 16 字节异或后，消除解原始特征。
// 注：解索引满足固定大小关系，此特征可被分析。
CH.random = xor(solution, seed[:16]) || Rand16
```

**服务端验证：**

```go
// 当前时间戳：
// Unix 时间，按分钟单位
Timestamp := Now / time.Minute

masked := CH.random[:16]
Rand16 := CH.random[16:]

// 防重放：
// 窗口内已经接受过的证明直接拒绝，不再验算。
// 缓存保留 3 分钟，盖住时间戳 ±1 分钟的容差。
if replayCache.Has(CH.random) {
    return false
}

// 验证：
// 会有多次冗余的尝试，但都是哈希计算，
// Accept 内部也是哈希验算通过了才会执行更耗时（＜40μs）的解验证。
// - 容错当前时间戳的前后 1 分钟。
// - 包容对端「有/无」自己的基网身份两种情况。
// - AppSeed 先用当前值。当前值失败时，再对保留的旧值各做一遍本循环。
// SelfAddr 本连接的目的地址，即客户端拨号时写进证明的 ServAddr。
// NodeID   服务端自己的身份 ID，已随基网身份提供。
for n := range [0, -1, 1] {
    ts := Timestamp + n

    // 对端持有本节点的基网身份
    seed = Hash256( domainTag || AppSeed || CH.SNI || NodeID || ts || Rand16 )
    if threshold.Accept( seed, xor(masked, seed[:16]) ) {
        replayCache.Put(CH.random)
        return true
    }
    // 对端冷启动，只知道本节点地址
    seed = Hash256( domainTag || AppSeed || CH.SNI || SelfAddr || ts || Rand16 )
    if threshold.Accept( seed, xor(masked, seed[:16]) ) {
        replayCache.Put(CH.random)
        return true
    }
}
return false
```


### 安全性

Equi-X 的解是 8 个索引，校验时要满足一组固定的大小关系，这是一个可检测的特征。但用掩码异或遮挡，避免解被直接检测分析。

常态连入绑定 NodeID，这是应用层的数据，审查者无法直接从 IP 报文里获取然后执行分析。但冷启动绑定 ServAddr 时则没有此保护。

算法抗 GPU/ASIC，必须使用 CPU。验算单次大约几十微秒，但审查必须要对每个候选报文真实验算。冷启动的连入证明无法回避这种验算，这是无法消除的风险。

连入工作量用 3 分钟的缓存去重避免重放攻击，但正常节点需要注意本机时间误差不能太大（≤1分钟）。

也因此，客户端需要尽可能避免纯粹的冷启动，比如保留曾经的历史记录、通过社会化方式获取一些当前在线的基网节点信息等。如果基网规模足够大，问题的严重性可能淡化。

> **补充：**
> 因为任意应用都可以借助于基网找到入口节点信息，所以冷启动的问题实际上只会落到基网节点上。
> 审查者旁路分析的反馈延迟，可能能被*首回即分享*的快速反应跳过——双方已经完成了有效交互。


## 响应分级

发起连接一端的初始 ClientHello 中即包含工作量证明，服务端进行验证。有如下两种情况：

- **非法连接**：无工作量证明或验证未通过，不予理睬或返回普通的 ServerHello（伪装）。
- **正常连接**：工作量证明验证通过，返回的 ServerHello 中包含自签名证书和*首分享*节点集。

> **注意：**
> 可达性测试通过轻量的 Ping/Pong 完成，无法实现验证。
> 可用性测试与可达性不同，此时才需要工作量证明，但计算「更重」。


### 首分享

因为 ClientHello 即包含认证，所以服务端返回的握手包中即可包含一批基网身份。这就是*首回即分享*的快速反应机制。

首分享的数据量遵循原则：*自签名证书 + 首分享 ≈ 常见网站CA证书链长度*，即首分享占用证书链中 `n证书-1` 的部分，以使得数据量外观上看不出差别。分享的数据存储在返回的 `EncryptedExtensions.Shared` 字段中（详见 [wTLS](https://github.com/cxio/wtls) 项目）。

> **实现：**
> 可能需要无效数据 padding 来匹配真实证书链长度，回避包长统计分析。

如果客户端已经获取到服务端的 `ECHConfig` 信息，则可以通过 `ClientHello.Extensions.Message` 来传递目标ID，使得首分享的信息也能支持距离逼近筛选。


#### 基网身份

首分享的是基网身份信息，但需要是可直连的 `Public/FullC` 节点，所以不含 `NATT`。

```go
(2)     版本（低成本）
(16)    公网IP，IPv4 嵌入 IPv6
(2)     连入端口
(32)    SPKIF，连接安全验证
(8)     Nonce，计算 NodeID 必须
```

每条信息 `60` 字节。如果传递 8 条，合计占用 `480` 字节。

**提示：**量子时代的证书体系（如默克尔树证书MTC）里，可借取的 TLS 握手容量可能更小。
