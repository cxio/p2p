# 攻击与应对

本网络的目标是尽可能协助应用发现节点，不提供节点本身的可信保证。

应用需要自行验证节点是否可信，或者可以脱离信任（比如文件分享P2P应用，是以数据指纹来保证文件的可靠性，而非信任分享者）。


### Sybil女巫攻击

**风险：** 攻击者创建大量虚假节点占据网络。
**对策：**
- 连入时的工作量证明。
- IP 前缀限额，同时作用在路由表 k 桶、k 近邻返回和登记。
- 新 NodeID 延迟 8 分钟才分享，长于一个 Epoch 加上时钟容差。
- 节点信誉：新节点权重低。


### 日蚀攻击

**风险：** 攻击者隔离目标节点，使其只连接到恶意节点
**对策：**
- 路由表 k 桶和近邻返回按 IP 前缀限额。
- 随机连接策略。
- 定期刷新连接。
- 高质量稳定节点优先分享和维持。
- 新身份（NodeID）延迟 8 分钟才扩散。


### DDoS放大攻击

**风险：** 广播搜寻机制被用于DDoS放大攻击
**对策：**
- 尽可能少的转播跳数（6跳小网域）。
- 节点搜寻只是为了找到入口，无需高频，因此搜寻速率受到严格限制（*2s/次*）。
- 对同一查询请求，中转节点不会重复转播，末端节点也不会重复回应（Proof 判断重复性）。
- 超出时间窗口的请求不会转发，时间窗口**±2**分钟（可配置）。
- 新查询的工作量证明绑定一个入口 NodeID，转播只来自已建立满 5 分钟的对等连接。


### 流量分析攻击

**风险：** 攻击者通过流量模式识别网络
**对策：**
- 伪装成浏览器发送 HTTP/2（TCP）或 HTTP/3（UDP）连接请求。
- 常态连入的工作量证明绑定 NodeID，解的字节由掩码保护，审查者无法验算。
- 冷启动绑定目标地址，证明可以被验算。客户端应带着历史节点或从其它渠道得到的节点上线。
- 可选支持 ECH（Encrypted Client Hello）。
- 无 ECH 时 ClientHello.SNI 考虑集成 Reality 伪装。


### 资源耗竭攻击

**风险：** 恶意节点大量消耗网络资源
**对策：**
- 连接数限制（每节点最大连接数）。
- 带宽限制（每连接最大带宽）。
- 请求频率限制（防止请求洪泛），参考「DDoS放大攻击」防范对策。
- 快速隔离机制（异常节点快速封禁）。
- 每一个请求都需要工作量证明，消耗攻击者能力。
