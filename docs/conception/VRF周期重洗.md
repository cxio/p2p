# 名识存储的 VRF 周期重洗

> **目的：** 消除名识存储位置的可预测性，把"定向围攻"从一次性的几何定位攻击，降维为每个周期都须重新支付的概率竞争。


## 问题

DHT 结构化查询中，名识的存储位置由静态异或距离决定（见 [设计](design.md) 的节点搜寻章节）。攻击者可以：

1. 对目标名识预先计算其存储区域。
2. 批量生成落入该区域的 Sybil 节点（NodeID 生成无成本）。
3. 垄断该名识的存储与应答位置，扣留记录（拒绝服务），阻滞目标服务成网。

定位精确，且一次布局长期有效，攻击成本极低。自由搜寻可规避定位，但效率低。本机制在保留结构化查询效率的前提下，剥夺攻击者的**确定性布局**能力。


## 核心机制

以固定时长的时间片周期（**Epoch**）为单位，每个 Epoch 重洗名识的存储位置，并要求存储者出示密码学抽签（VRF）资格证明。

### 第一层：位置重洗

存储键由 Epoch 随机种子派生：

```go
// @RandX 为离散因子，详见 design.md。
StoreKey := Hash256( Seed_e || 名识 || RandX )
```

- 名识记录不再存储在"离名识近"的节点，而是存储在离 `StoreKey` 近的节点（Kademlia 路由方式不变）。
- 每个 Epoch 更换 `Seed_e`，全网名识的存储位置整体重洗。
- 发布方与查询者计算的 `StoreKey` 键小范围随机分布，依赖随机碰撞触及目标，无需任何协调。
    - 范围足够小 + 目标足够多 => 碰撞几乎必然成功。
    - 如果随机的 `StoreKey` 临近目标没有相应记录，再次尝试即可。

> **注：**
> 这里的「名识记录」即包含名识内容的节点记录，特指用于依名识登记。


#### 更新周期

- 1 小时（`Epoch`）一次转储动作，但这仅是部分迁移（按分批规则）。
- 12 个小时一次全量转移，即全部名识分 12 批转储。分批判断从旧的 StoreKey 本身取依据（首4字节取整 % 12）。

分批判断从 StoreKey 而非名识上取依据，可以获得一种不确定性。这可以让攻击者难以固化成本预算。当然，这也可能让某些名识的迁移间隔时间翻倍延长至24小时（最恶劣情况）。


#### 转储认证

名识记录从一个节点转储到一个新节点时，攻击者可能对接收数据的新节点采取 DDoS 攻击，以阻止数据的转移（破坏位置重洗机制）。因此下面设计了第二层保护：**资格抽签（VRF）**，详见后文。

因为存在资格抽签机制，中签者就拥有资格证明，所以对转储的双方就可以实施认证约束，避免攻击者节点混入和破坏。认证过程如下：

1. 转出者（旧存储者）计算新的 StoreKey，查找符合条件的新存储者（接收者）。
2. 转出者连接并询问接收者是否拥有资格（中签），但仅是询问，不要求对端提供证明。
3. 新存储者计算自己的资格，如果中签，回答是，并先要求旧存储者提供证明。
4. 旧存储者提供证明，新存储者验证合法后，提供自己的证明。
5. 旧存储者验证新存储者的资格证明，如果合法，则开启数据的转储过程。

在这一流程中，没有资格证明的第三方无法混入，转储是身份安全的。


#### 注册存储

一个新的节点注册名识记录，需要存储到与该名识对应 StoreKey 键相邻位置的节点上，这是初始的登记存储，与转储不同。

为避免任意节点登记大量垃圾记录淹没正常节点，注册存储引入票券延迟机制：写入前需先向存储者申领票券，等待一个短暂延时后凭票写入。延时的长短由存储者根据自身情况灵活决定（默认 `60s`，可配置）。

凭票申请写入并不是绝对的，存储者有权根据自身负载情况或对申请节点的评估，决定是否再次延迟（重新发票）。

另外，注册存储也需要检查存储者是否有资格。这是必须的，因为存储者在转储时需要证明自己是合法的旧存储者。


### 第二层：资格抽签（VRF）

仅有距离不足以成为合法存储者。节点还须在本 Epoch 中签（邻域范围局部抽签）：

```go
// @RandX 离散因子
// - 注册时：由信息发布者提供。
// - 转储时：由原存储者提供（可新生成）。
ticket, proof := VRF( 节点私钥, Seed_e || 名识 || RandX )
// 合法条件: ticket < τ （阈值参数）
```

- **不可预测**：无私钥者无法预知他人是否中签。
- **可验证**：应答时出示 `proof`，查询者以节点公钥（SPKI）验证。
- **不可定向**：攻击者生成 Sybil 节点后，中签与否仍是概率事件。

VRF 密钥复用节点身份私钥（即自签名证书密钥，套件选型留待提案层）。

> **提示：**
> 记录内容可信度始终由记录自身保证。抽签只决定"谁有资格服务"，不引入新的信任点。

> **实现：**
> 副本选取顺序：发布方优先写入中签者，中签者不足时按距离递补；查询方先询问中签者，不足或无响应时按距离递补询问。


## 随机信标

`Seed_e` 必须满足：Epoch 开始前**不可预测**、开始后**全网一致**、**不可被单方操控**。

- **主用**：drand 公共随机信标（阈值 BLS 签名，每 `30s` 一轮）。Epoch 编号与 drand 轮次均由时间线性派生，节点独立计算，取 Epoch 起始时刻对应的轮次输出作为 `Seed_e`。
- **降级**：信标不可达时，冻结当前 Epoch 的存储映射（不轮换），直至信标恢复。此期间名识查询自动降级至*自由搜寻*兜底。

> **权衡：**
> drand 是外部信任假设（需阈值多数串谋才能操控），与完全无中心的愿景存在张力。但它只在 Epoch 边界被轻量引用（一次极小查询），不介入运行时；且操控收益仅限一个 Epoch 的提前布局权，仍须面对抽签。
> 理论上，未来 drand 网络的稳定性实际上可以籍由基网本身得到加强。这是一种互补增益的关系。


## 时序与平滑

- **Epoch 时长**：默认 `1h`（可配置）。编号 = `unixtime / epochLength`，依赖节点本地时钟，误差容忍沿用 `±5分钟`。
- **双窗口查询**：查询者同时查询当前与前一个 Epoch 的 `StoreKey`，容忍边界处的发布迁移延迟。
- **记录 TTL**：存储记录有效期为 `2` 个 Epoch，过期即弃，存储者无需长期持有数据。
- **续约责任**：由转储者在每个新 Epoch 重新计算 `StoreKey` 并写入。


## 参数

| 参数 | 默认值 | 说明 |
|------|--------|------|
| epochLength | `1h` | 时间片周期时长 |
| 中签阈值 τ | 期望副本 `20` | 由目标副本数与网络规模估计换算，设硬下限 |
| 票券延迟 | `60s` | 写入前等待时长 |
| 记录 TTL | `2 Epoch` | 过期丢弃 |
| 查询窗口 | 当前 + 前 `1` 个 Epoch | 平滑边界 |


## 新增风险与对策

### 信标依赖

**风险：** drand 被封锁或不可达。
**对策：** 冻结映射 + 自由搜寻兜底；信标查询数据量极小，可走任意代理通道。未来可与基网本身结合，互为保护。

### 信标操控

**风险：** drand 阈值多数串谋可预知种子。
**对策：** 收益仅限单 Epoch 的提前布局，仍受抽签约束。

### 时钟攻击

**风险：** 伪造时钟误导 Epoch 边界。
**对策：** Epoch 由本地时钟派生，偏离者自然与全网错位而无法协作；陈旧记录被 TTL 拒绝。

### 稀疏区域副本不足

**风险：** 某些 Epoch 中签名识的中签存储者过少。
**对策：** 阈值设硬下限；不足时邻近未中签节点按距离递补服务（见「资格抽签」实现注），内容可信度由节点ID哈希绑定。

### 路由层污染

**风险：** 攻击者以大量 Sybil 包围 `StoreKey` 邻近区域，污染迭代路由过程本身（与抽签无关的 Kademlia 通病）。
**对策：** 与「日蚀攻击」对策同源：地址池多样性配额、随机多径并发查询、定期刷新连接。详细定量分析留待仿真验证。


## 与自由搜寻的分工

- **常态**：结构化查询 + 周期重洗，高效且不可定位。
- **信标失效 / 极端审查**：降级为自由搜寻（随机扩散 + 微广播），以效率换存活。

两者不是主备关系，而是连续谱：重洗的不可预测性越弱，自由搜寻的权重越高。


## 待决问题（留待 Decision/Proposal）

1. VRF 具体套件（如 RFC 9381 的 ECVRF-ED25519）及其与节点证书密钥的复用关系。
2. 全网规模估计方法（地址池采样 / gossip 统计），用于 τ 换算。
3. τ 的换算公式与硬下限值。
4. 票券协议细节（防囤积、防预支、跨 Epoch 失效）。
5. 节点信息记录的编码封装格式，与 Epoch 字段的衔接。
