# 实现参考（Guidance）

## 节点池

### 候选池

暂存可直接连入的 `Public` 和 `FullC` 类节点信息，当准备分享时，从中随机抽取部分节点（比如15个）。

候选池节点也是基网主动连出时的目标，当进行连接切换时就会从中随机选取一个或几个节点。而当连接建立后，节点也会从对方获得分享（可能有一个随机延时，以避免流量特征）。

收到的分享节点会测试其可达性，但出于“毒IP”的设计，只会测试部分成员（局部模糊策略）。

> **注意：**
> 除 `Public` 和 `FullC` 类型之外的节点不能对外分享，因此不进入候选池。
> 候选池中只有节点的连系信息，并没有当前连接的实例（测试后即已断开）。

候选池大小有一个上限值，用户可配置，避免低性能机器的资源消耗过多。


#### 毒IP影响

候选池仅存储可直接连入的 `Public/FullC` 节点，是一种逻辑上的要求。实际上候选池中包含未测试的节点（毒IP策略），因此未测试的节点可能无法直接连入。

节点取候选池成员建立新连接，如果失败，丢弃该节点信息即可（自然滤除）。


#### 工作量约束

虽然分享进入候选池的节点不会全部测试，但为了避免伪造节点信息实施 Sybil 攻击，分享的每一个节点信息需要附带工作量证明。该证明通过一个 32 字节的附加信息（`SaredPeer.Proof`）提供。

算法伪代码：

```go
// @AppSeed 32字节客户端固定种子。
// @ReceiverAddr 接收者公网地址（IP:Port）。
// @SharerAddr 分享者公网地址（IP:Port）。
// @Timestamp 当前时间戳，容许 `±5分钟` 的误差
// @Random16 随机字节序列，用来求解工作量（16字节）。
// @SharedPeer.Addr 被分享的节点的地址（IP:Port）。
challengeSeed := SHA256( AppSeed || ReceiverAddr || SharerAddr || Timestamp || SharedPeer.Addr || Random16 )

// @appNonce: uint64 随机数，客户端内置。
// 客户端工作量运算：appNonce 作为内部 nonce 不变，通过调整 Random16 来改变 challengeSeed 求解。
// @solution 返回的8个哈希索引（每索引2字节），共16字节。
solution, err := equix.Solve(challengeSeed, appNonce)

// 与分享的节点信息同时提供
// 接收分享节点信息的节点据此验证每一个分享节点的工作量约束是否满足。
SharedPeer.Proof = solution || Random16
```

注意，工作量是由分享者而非请求者实施的。攻击者可能随意请求分享，以此消耗分享者资源。因此作为分享者，需量力而行：如果判断对方为恶意，可不提供分享，避免资源消耗。

这是一种数据流转的代价，为避免攻击者无成本创建虚假数据。分享者只能通过限制分享频率、数量等方式来间接控制资源消耗。


### 组网池

即当前组网节点的*连接池*，维持基网的持续运行。组网池分为两个部分：**连入**和**连出**。

主动连出的节点数上限通常比连入节点数上限低，但连出的都是 `Public/FullC` 类节点，而连入的则是任意NAT类型的节点。

组网池中的节点连接需要维护，比如维持适当的规模、不定时切换节点、接受请求分享候选池中的节点或请求对端分享节点。

> **注意：**
> 组网池不是候选池，候选池中只有节点信息而非实际连接。

如果节点候选池中有效的节点不足，主动连出受挫，节点可以主动请求任意连接方分享新的节点信息。


#### 转发策略

在节点对消息的转播中，并不是全量转发，而只是随机选取一部分节点转播。这里有一个策略：

- 假设转发量配置为10，正常情况下连入与连出各取一半（5个，配置值的一半）。
- 先取连入的节点，如果数量不足（如连入池只有4个），则剩余部分（6个）全部从连出节点池中获取。

这可以自适应连入节点数不足的情况，然后让连出节点占优（获得更多的分配）。


#### 更新策略

组网池中的节点连接需要定期更新，以维持网络的健康和稳定。更新策略包括：

- 每2~3分钟随机抽取一个连接用于更新（新连接建立后会断开该旧连接）。
- 会检查时间戳，抽取的连接至少需超过10分钟才会被更新，否则另选其他连接，避免不稳定性。
- 若为8个连出，大概16~24分钟会完整更新一次。这有一定的模糊性，包容。



## 其它事项

### 初始节点植入

初始节点可以由应用内置或用户配置导入。如果两种方式都没有，则采用暴力发现的方式遍历IPv4地址进行搜寻。

在网络发展的初期，基网的规模不大，在App中植入一些已知的基网节点是必要的。


### 被动分享

节点不应当主动分享自己候选池中的信息，而应该在对方请求后才提供。这更简单也更合理。

> **注：**
> 客户端在连入服务器时，服务器会在TLS握手回应中附带一批节点信息（首分享）。
> 这既是客户端连入请求的默认逻辑，也强化了节点信息扩散的鲁棒性。


### 关于服务子网

服务子网是一些公共的服务，比如 STUN 探测和打洞服务、数据中转服务等。它们由单独的项目创建，这里无需涉及。
