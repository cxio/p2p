# 获取 IP 回显（准备）

节点生成连入工作量证明时需绑定 `ClientIP`，本方案解决「工作量求解之前不知道自己公网地址」的问题。


## 结论

回显放在**基网的拨号与监听**里，放在调用 wTLS / QUIC 之前。wTLS 更底层，但这一步比它更早。QUIC Retry 同样来不及。


## 做什么

客户端在求解连入证明之前，向**即将拨号的同一目标、同一种传输**问一次：你看到的我的源地址是什么。

- 问询不完成 TLS，不带工作量证明，不带首分享，不进入节点记录。
- 服务端只把**这个报文的源地址**抄回去。请求报文正文里没有地址字段，避免被拿来把回应打到任意目标。
- 客户端用抄回的地址作为 `ClientIP`，再按 [工作量认证](1.工作量认证.md) 求解，然后才拨号。

问询与正式拨号可以是两个套接字。连入证明只绑 IP、不绑端口，对称 NAT 换端口不影响。TCP 问询不能代替 UDP 拨号，反过来也不行：两种传输的公网地址可能不同。IPv4 与 IPv6 分开问、分开记。


## 何时问

1. 该传输、该地址族没有缓存：先问，再求解，再拨号。
2. 有缓存：直接求解并拨号。拨号失败时，问一次、再求一次、再拨一次。第二次仍失败则停止，不循环。
3. 问询超时或没有回应：这次拨号失败。不改用一份不绑 `ClientIP` 的证明。

缓存的是完整地址（IPv4 映射成 IPv6 的 16 字节，或原生 IPv6）。


### 分支备用

应用可配置一台或几台普通的公共 STUN 服务器，向 STUN 服务器请求回显自身的 IP 地址。

公共 STUN 服务器是普通大众需求，可以避免被审查者重点关注。或者，用户也可以手工注入/配置IP（人工渠道获取），增强灵活性。

> **说明：**
> 本分支主要用于审查严重的环境，外部正常世界用原简单方案即可。


## 报文

固定长度，便于从 QUIC / TLS 里剥出来。客户端 Initial 至少填充到 1200 字节，问询只有 32 字节，不会和它相混。

**请求（32 字节）：**

```go
(4)  Magic   0xE1 0x90 0xC1 0x01   // 分拣用，不是密钥
(1)  Ver     1
(27) Pad     0
```

**回应（20 字节）：**

```go
(4)  Magic   同上
(16) IP      服务端看到的源地址，IPv6 形式；IPv4 用 v4-mapped
```

无端口、无 cookie、无节点信息。Magic 在冻结前可以改，两端必须相同。

服务端对每个源地址限速，建议间隔不少于 **2 秒**，超限则丢弃、不回应。回应短于请求，且只发回该源地址。


## 接在哪里

```
缓存或回显得到 ClientIP
        │
        ▼
按 1.工作量认证.md 求解（绑定 ClientIP）
        │
        ▼
wtls.GetClientRandom / QUIC 拨号
        │
        ▼
服务端 VerifyClientRandom（用本次连接的源地址）
```

| 位置 | 职责 |
|------|------|
| 基网拨号 | 决定要不要问；发 32 字节；收 20 字节；写入缓存；再调用现有求解 |
| 基网监听 | 在把报文交给 QUIC 或 wTLS 之前看长度和 Magic。对上了就回应并结束；其余原样交给现有栈 |
| `wtls` | 不改。继续只负责 `CH.random` 的写入和验证 |
| `quic-wtls` | 不改。不使用 Retry 携带地址 |

UDP 用包在 `PacketConn` 的读路径上拦截。TCP 用接受连接后的前 8 字节判断：是 Magic 则回应并关闭；是 TLS 记录（首字节 `0x16`）则把已读字节放回，交给 wTLS。问询用独立的短连接，不在同一条 TCP 上接着做握手。


## 不解决的事

冷启动本身可被审查者识别。回显只在没有可用缓存时出现，识别面限于这一次问询。有缓存的拨号仍然直接是带证明的 ClientHello。
