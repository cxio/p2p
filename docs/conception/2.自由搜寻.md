# 自由搜寻规范

自由搜寻采用微广播方式，但严格约束中转跳数，尽可能消解消息洪泛的问题。同时，每一个查询都需*工作量证明*，以抑制垃圾查询风暴。

- **搜寻路径**：`客户端 => 首跳节点 => 次跳中转 => 末端节点`。
- **扩散规模**：总跳数**3**，每级跳转最多向**8**个下级节点转发请求。
- **全量回传**：末端返回**8**条信息，中转回传下级返回的全部信息。


## 搜寻请求

搜寻请求包称为*询问包*，含如下内容。

> **注：**
> 下面的伪代码中：`(n)` 表示字节数，`(~)` 表示变长字节数。

```go
(2)     Ver:        版本号。
(8)     ID:         标识本次询问，用于回复包中对应其源请求。
(8)     Timestamp:  询问时间戳（Unix，毫秒）。
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
(~)     KeyPrefix:  目标名识键前缀（≤32）。
(32)    Proof:      工作量证明
(1)     Hops:       剩余跳数，初始值2，最低到0。
(1)     HPKE：      加密用公钥素材：Hybrid Public Key Encryption
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
(~)     Extra：     可选，灵活空间，≤64 字节。
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
```

> **设计：**
> 搜寻目标为键前缀，以支持模糊查询的隐私保护策略。

节点对同一查询请求不会重复转发或回应，相同判断取 Proof 字段值比较（工作量已绑定必要字段，且已先验证）。


## 回应消息

回应的消息称为**回复包**，按广播的路径原路回传。

结构如下：

```go
(2)     Ver：       版本号。
(8)     ID：        原询问包中的ID，用于上级对应请求源。
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
(~)     Cipher：    应答者的协商密文，封装了共享密钥。
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
注：以下信息已用共享密钥加密
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
(8)     Timestamp:  回复时间戳（Unix，毫秒）。
(~)     KeyPrefix:  目标名识键前缀，与询问包内的同字段值相同，用于核实确认。
(~)     Nodes:      分享的节点信息集。不超过8个节点。
                    与首分享不同，此节点信息包含完整字段数据。
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
(~)     Extra:      可选，可能需要的附加信息，≤255 字节。
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
```


## 工作量证明

**通用部分：**

```go
import "github.com/cxio/equix-cgo/puzz"

// 命中率：10%
// 固定配置，针对当前流行PC，约 100~200 毫秒成本。
threshold := puzz.FromProbability(0.1)

// 基础信息：
// 查询路径上不支持 Sym NAT 节点，即端口需稳定。
// 实现：节点需从相同的本地端口连接各方。
// domainTag  查询专用域标识：base-net.Query@v1
// Addr1      首跳节点公网地址（IP:Port）
// Nonce      首跳节点返回的随机数（8字节）
// KeyPrefix  查询目标名识键前缀（询问包字段）
// ID         询问ID（询问包字段）
// Timestamp  询问包时间戳（询问包字段）
baseInfo := domainTag || Addr1 || Nonce || KeyPrefix || ID || Timestamp
```

**每查询求解：**

```go
// 求解：
// Rand16   工作量求解者寻找的16字节随机数，会作为证明的后半段
// solution 一个合法解，2*8 = 16字节
var Rand16, solution
for {
    // 每轮生成新的 Rand16
    Rand16 = ...
    solution, _ := threshold.Try( Hash256(baseInfo || Rand16) )
    if solution != nil {
        break
    }
}
Proof := solution || Rand16
```

**中转者验证：**

```go
// 验证解：
// - 首跳节点验证：自己知道 Addr1 和 Nonce
// - 次跳节点验证：Nonce 由首跳节点提供，Addr1 为对端（首跳）地址
// - 末端节点：无需验证，直接执行查询。
Rand16 := Proof[16:]
solution := Proof[:16]
seed := Hash256( baseInfo || Rand16 )

return threshold.Accept( seed, solution )
```

这里，中间转播者仅负责验证工作量并转发请求，最大化离散和末端规模。
